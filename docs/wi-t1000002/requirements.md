# 主题样式优化 — 需求文档

- Work Item：`wi-t1000002`
- 阶段：requirements
- 文档版本 / 基线状态：v1（首次需求文档，迭代任务）
- 任务类型：对现有应用做视觉主题优化，不新建产品
- 决策：ready

## 1. 项目背景与目标

**现状（已读取当前实现）**：现有产品为纯前端单页任务看板（Kanban），结构为 `app/index.html`、`app/style.css`、`app/store.js`、`app/app.js`；零外部依赖，使用 CSS 自定义属性实现 light/dark 双主题，深色模式偏好持久化。当前视觉基调为 Jira 风格：高饱和蓝色主色（`--accent-blue: #0052cc`）、较强边框与阴影、较小圆角（`--radius-sm: 4px`）、密集排版。

**用户明确提出的目标**：主题样式优化，主题变成简约柔和的风格。

**成功结果**：用户用浏览器打开应用后，界面整体呈现简约、柔和的视觉风格；原有的全部功能行为与 light/dark 主题切换、偏好持久化均不受影响。

**本文档范围**：只描述本次样式优化的可验收结果，不新增产品功能，不改信息架构。

## 2. 用户旅程与关键场景

### JS-01 打开应用查看新主题（端到端）
使用者打开页面 → 首屏即在默认（浅色）主题下呈现柔和风格 → 观察到无高饱和刺眼色块、无强对比硬边框、阴影轻柔、组件观感统一。

### JS-02 切换深色模式
使用者点击顶栏主题切换按钮 → 深色主题同为柔和风格（而非旧的高饱和/强对比深色）→ 刷新页面后仍保持所选主题偏好。

### JS-03 日常任务操作中的视觉一致性
使用者在创建、内联编辑、拖拽、搜索筛选、列显隐、删除后撤销等操作过程中，所出现的卡片、看板列、徽标、输入框、提示条、对话框、错误提示条都符合统一的柔和风格，且文字清晰可读。

## 3. 分模块功能需求

### M1 主题基调与色彩令牌（浅色 + 深色）
- 用户提出：整体主题「简约柔和」。（用户明确提出，无可观测细节）
- **推荐基线（可安全推导，非用户已确认事实）**：在不改变现有主题变量结构的前提下，整体基调调整为低饱和、柔和的配色方向——主色与强调色降低饱和度；背景与分隔使用偏柔和的浅中性色阶；避免纯黑/纯白造成的强对比；圆角统一偏柔和（在当前基础上适度增大并保持一致）；阴影改为更轻、更弥散；边框弱化或改为更浅的分隔线；字重与字号层级更克制。
- 浅色与深色两套主题使用同源的柔和基调，不得只调整其中一套。

### M2 组件级样式覆盖（无遗漏）
优化须覆盖现有界面中全部可见组件，且每类组件在浅色、深色下均一致：
顶栏（标题、图标按钮）、搜索栏（含聚焦态）、看板列容器、列头与计数徽标、任务卡片（含 hover/拖拽/已完成态）、新建任务内联编辑器、卡片内联编辑表单（输入框、下拉、日期）、优先级徽标（高/中/低）、截止日期徽标（含逾期）、添加任务按钮、空状态、删除撤销提示条（Snackbar）、确认/损坏提示对话框与遮罩、错误提示条、拖拽悬停指示。
- 要求：不存在任何未随主题更新的旧样式残留（例如残留旧高饱和蓝、旧阴影或旧圆角值）。

### M3 主题切换与偏好持久化（保持现有行为）
- **已确认的产品规则（现有基线，必须保留）**：顶栏提供主题切换入口；切换后主题立即生效；偏好被持久化，刷新或重新打开后保持。
- 本次优化不得破坏上述行为，也不得新增第三种主题模式。

### M4 交互状态与信息辨识度
- 交互反馈（hover、focus、active、拖拽悬停、禁用态）在优化后仍清晰可见，且观感柔和（不出现刺眼高亮或硬描边）；键盘焦点在可见范围内可辨识。
- 优先级徽标、逾期标记、已完成任务等状态仍可被使用者一眼区分（柔和 ≠ 无法区分）。

## 4. 非功能要求

- **NFR-01 可读性**：柔和化后正文文字与其背景仍保持清晰可读（正文级文字对比度不低于约 4.5:1 的量级；推荐基线）。柔和不得以牺牲可读性为代价。
- **NFR-02 无功能回归**：创建、内联编辑、拖拽排序、搜索筛选、列显隐、删除与撤销、JSON 导出、数据持久化、存储异常恢复、数据损坏处理等既有行为不变。
- **NFR-03 零新增依赖**：不引入 UI 框架、组件库、外部字体或图片外链；保持纯前端零依赖。
- **NFR-04 无性能退化**：样式加载与主题切换无可感知延迟（均为 CSS 层面的调整）。
- **NFR-05 状态不被破坏**：主题优化不得影响已保存的用户任务数据与主题偏好数据。

## 5. 明确不在当前范围内的能力

以下均为用户未提出且现有基线未确认的内容，**不纳入本次范围**：
- 不新增任何产品功能，不改页面结构、信息架构与交互流程。
- 不新增第三种主题（如高对比、彩色、护眼模式），不提供主题自定义或上传能力。
- 不替换现有图标方案与字体族。
- 不要求移动端/窄屏专项适配（用户未提出）；现有响应式布局保持现状，不因本次优化新增或扩大窄屏承诺。
- 不做品牌名称、文案与 Logo 变更。

## 6. 验收场景

每条验收条件使用稳定唯一编号；强制程度、入口类型、前置条件、动作、可观察预期结果、证据类型与适用角色均记录在同一条目内。适用角色统一为「未区分角色（当前产品为单使用者场景，用户未要求角色体系）」。

### AC-01 浅色主题首屏呈现柔和基调
- 强制程度：必须
- 入口类型：UI / 浏览器
- 前置条件：以默认浅色主题打开应用首页
- 动作：观察首屏整体观感与主题变量
- 预期结果：界面整体为低饱和柔和配色，无高饱和主色的大面积填充；圆角与阴影呈柔和观感；不存在旧的高饱和蓝色强调残留
- 证据类型：浏览器截图 + 主题 CSS 变量核对
- 适用角色：未区分角色

### AC-02 深色主题同样柔和
- 强制程度：必须
- 入口类型：UI / 浏览器
- 前置条件：应用可切换主题
- 动作：切换到深色主题并观察整体观感
- 预期结果：深色主题与浅色主题同源柔和基调；背景不为纯黑、文字不为纯白强对比；无旧的高饱和强调色残留
- 证据类型：浏览器截图 + 主题 CSS 变量核对
- 适用角色：未区分角色

### AC-03 组件样式全覆盖无遗漏
- 强制程度：必须
- 入口类型：UI / 浏览器
- 前置条件：浅色与深色主题各检查一次
- 动作：逐一查看第 M2 节列出的全部组件
- 预期结果：全部组件均采用统一柔和基调；任一组件均无旧样式残留
- 证据类型：组件清单核查记录 + 截图
- 适用角色：未区分角色

### AC-04 状态信息仍可区分
- 强制程度：必须
- 入口类型：UI / 浏览器
- 前置条件：存在高/中/低优先级任务与逾期、已完成任务
- 动作：观察优先级徽标、逾期标记与已完成卡片
- 预期结果：三类优先级与逾期、完成状态仍可被明确区分；柔和化后不出现混淆或不可辨
- 证据类型：浏览器截图
- 适用角色：未区分角色

### AC-05 交互反馈清晰且柔和
- 强制程度：必须
- 入口类型：UI / 浏览器
- 前置条件：界面可交互
- 动作：对卡片、按钮、输入框与看板列执行 hover、聚焦、拖拽悬停等操作
- 预期结果：每种状态均有可见反馈，且反馈柔和、不刺眼；键盘聚焦可见
- 证据类型：浏览器截图 / 操作记录
- 适用角色：未区分角色

### AC-06 主题切换与偏好持久化不回退
- 强制程度：必须
- 入口类型：UI / 浏览器
- 前置条件：默认浅色主题
- 动作：切换到深色主题后刷新页面（或重新打开）
- 预期结果：切换即时生效；刷新后仍保持所选主题；仅存在浅色/深色两种模式，无第三模式
- 证据类型：操作记录 + 刷新后截图
- 适用角色：未区分角色

### AC-07 既有功能无回归
- 强制程度：必须
- 入口类型：UI / 浏览器
- 前置条件：主题优化已完成
- 动作：依次执行创建任务、内联编辑、拖拽排序、搜索筛选、列显隐、删除并撤销、JSON 导出
- 预期结果：全部功能行为与优化前一致，无功能异常
- 证据类型：功能操作记录
- 适用角色：未区分角色

### AC-08 零新增外部依赖
- 强制程度：必须
- 入口类型：源码核对（非 UI 能力）
- 前置条件：优化后的源码可见
- 动作：核对外链、依赖与字体引用
- 预期结果：未新增外部依赖、外链字体或图片引用，保持纯前端零依赖
- 证据类型：源码核对结论
- 适用角色：未区分角色

### AC-09 可读性下限
- 强制程度：必须
- 入口类型：UI / 浏览器
- 前置条件：浅色与深色主题各检查一次
- 动作：阅读标题、正文、次要文字与徽标文本
- 预期结果：正文级文字与其背景对比度达到约 4.5:1 量级，文字清晰可读
- 证据类型：对比度核对记录 + 截图
- 适用角色：未区分角色
