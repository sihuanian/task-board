## 1. 项目背景与目标

任务看板以三列（待办 / 进行中 / 已完成）呈现个人任务，采用看板式卡片布局，支持创建、内联编辑、拖拽改状态、删除（约 5 秒撤销）、搜索、深色模式切换、列显示/隐藏、优先级与截止日期、JSON 导出，并基于本地存储做版本化持久化与错误恢复（存储异常横幅、数据损坏恢复对话框）。应用为本地单用户工具，无账号体系与角色分级。

本次需求是**界面与交互体验的整体优化**，业务能力不变，重点在于「更好看、更好用」：

1. 视觉更**简约**：减少冗余视觉噪声，让层级、留白、信息密度更克制。
2. 配色更**舒服**：浅色与深色主题下都保证舒适对比度与统一色调。
3. 交互动画更**丝滑**：补齐并统一各类状态切换（悬停、按下、展开/收起、进入/退出、拖拽、提示）的过渡，避免生硬跳变。
4. 操作按钮的可理解性**评估**：评估图标型按钮是否需要 Tooltip（功能说明提示），使含义无需猜测。

成功结果：用户打开看板时视觉更干净、配色不刺眼；操作有顺滑反馈；每个图标按钮的含义都能通过悬停或键盘聚焦直接理解；既有功能与已保存数据不受影响。

### 1.1 当前基线与差距（现状观察，供后续阶段参考）

以下为对现有实现的实际观察，说明本次需求要弥合的差距（非需求本身）：

1. 图标型按钮（头部导出、恢复列、深色切换，列头隐藏按钮，卡片上的图标操作）目前同时带有原生 `title` 与非空 `aria-label`；但原生 `title` 仅在鼠标悬停约 1 秒后出现，**不随键盘聚焦触发**，样式不可控、出现节奏突兀。
2. 过渡节奏不统一：按钮约 0.15s、卡片阴影/透明度约 0.15–0.2s、优先级徽章约 0.25s；列隐藏/恢复为瞬时 `display:none` 切换，错误横幅、撤销提示、对话框显隐同样缺少过渡。
3. 深色主题已存在（`[data-theme="dark"]` 整套覆盖），需复核其对比度舒适度与刺眼感（大面积高对比、高饱和元素）。
4. 无「减少动态效果」偏好下的动效降级（`prefers-reduced-motion`）。
5. 样式已存在一套 CSS 变量体系（既有基线事实，非本次新增要求；是否沿用或重组由设计阶段决定）。

## 2. 用户旅程与关键场景

### 场景 A：用户希望界面更清爽、不刺眼

1. 用户打开看板，第一屏即看到标题区、搜索、列与卡片，层级清晰、留白适度。
2. 用户在浅色主题下长时间使用不觉刺眼；切换到深色主题后同样舒适，色调统一。
3. 用户无需刻意「学习」即可区分：标题、次要文字、弱化文字、边框、可点击元素。

### 场景 B：用户希望操作有顺滑的反馈

1. 用户悬停卡片或按钮，界面以平滑过渡给出「可操作」暗示；按下有即时反馈。
2. 用户切换主题、隐藏/恢复列、打开编辑器、触发撤销提示时，元素出现/退出有流畅过渡而非瞬时跳变。
3. 用户拖拽卡片时，占位与落点反馈连贯，松手后卡片平滑归位。
4. 动效不拖沓：过渡完成前用户仍可继续下一步操作，不被动画阻塞。

### 场景 C：用户不理解某个图标按钮的含义

1. 用户把鼠标移到图标按钮上，短暂延迟后出现说明文字，解释该按钮的功能。
2. 用户用 Tab 键把焦点移到该按钮上，同样能看到功能说明。
3. 屏幕阅读器用户通过控件的可访问名称获得与提示一致的含义；提示本身不遮挡用户正在进行的操作。

## 3. 状态模型与业务规则

本次为纯 UI/交互优化，**不改变业务数据模型与业务规则**。确认以下不变式：

- 任务、列、优先级、截止日期、可见性等数据语义与持久化行为保持不变。
- 任务三列状态（待办 / 进行中 / 已完成）与拖拽转换语义不变。
- 删除撤销窗口（约 5 秒）与撤销行为语义不变。
- 搜索过滤语义不变（按标题过滤）。
- 存储异常提示与数据损坏恢复流程语义不变。
- 所有既有功能（创建/编辑/删除/拖拽/搜索/导出/深色模式/列隐藏恢复/错误恢复）均保留，仅调整其视觉呈现与交互反馈。

界面反馈状态（本次明确的 UI 状态语义，供设计阶段细化）：

| 状态组 | 取值 | 语义要求 |
| --- | --- | --- |
| 控件交互态 | 默认 / 悬停 / 按下 / 聚焦 / 禁用 | 每个状态有可观察差异；状态间切换平滑；焦点态可辨识（不因简约而移除） |
| 主题 | 浅色 / 深色 | 切换全局即时生效；两套主题下元素颜色协调 |
| 列可见性 | 显示 / 隐藏 | 切换有过渡反馈；隐藏列可经「恢复列」找回 |
| 提示 | 隐藏 / 显示 | 由悬停或键盘聚焦进入；由移开、失焦或操作确认退出 |
| 删除撤销 | 出现 / 到期消失 | 出现有过渡；撤销窗口内可一键恢复 |

## 4. 分模块功能需求

### M1 视觉层级与简约

- 同类元素（卡片、按钮、徽章、输入框、对话框）在间距、圆角、阴影、描边上使用一致规格；规格差异仅用于表达层级差异。
- 标题、次要文字、弱化文字三级文字层级可通过字号/字重/颜色明度区分。
- 减少视觉噪声：非重点的装饰性描边、重复边框、过重阴影合并或弱化；整体留白适度。
- 简约不得牺牲可辨识性：可点击元素保留清晰的可点击暗示（悬停反馈、指针形态、焦点环）。
- 不新增业务信息密度（不增加字段、统计或新控件）。

### M2 配色舒适（浅色与深色）

- 浅色与深色两套主题均需达到「舒服」：正文与背景对比充足、不刺眼；大面积背景避免高饱和色。
- 深色主题避免大面积纯黑与强发光元素，避免深浅主题切换时的眩光反差。
- 语义色（优先级徽章等）在两套主题下均与背景协调且可辨识（如「高」优先级在两主题下都能一眼区分）。
- 主题切换即时全局生效，且切换过程不出现错色闪烁。
- 推荐基线（设计阶段可微调，不得低于可读下限）：界面普通文字对比度不低于 WCAG AA 正文标准（4.5:1），正文主文本建议达到约 7:1 或更高。

### M3 交互动效

- 悬停、按下、聚焦、选中、禁用等控件状态切换均有平滑过渡。
- 列隐藏/恢复、任务编辑器出现、错误横幅、撤销提示、损坏恢复对话框等出现/退出有过渡，而非瞬时显隐。
- 拖拽过程中占位提示与落点高亮连贯，松手后卡片平滑收敛到目标位置。
- 主题切换时整体颜色过渡平滑。
- 推荐基线：常规状态过渡时长在 100–250ms 量级，同一应用内节奏一致；过渡期间不阻塞用户下一步操作（不使用延迟操作的等待式动画）。
- 动效只作为状态变化的反馈，不新增与业务无关的装饰性循环动画。

### M4 图标型按钮功能提示（评估结论）

评估对象：所有仅以图标呈现、无文字标签的操作控件（当前基线包括：头部导出、恢复列、深色切换；列头隐藏按钮；卡片上的图标操作）。

评估结论：**需要补充功能说明提示**。理由：

- 图标含义依赖用户记忆与猜测，无法自解释；
- 现有原生 `title` 仅鼠标悬停约 1 秒后出现，不随键盘聚焦触发，样式与出现节奏不可控，触屏场景不可用。

需求结果：

1. 鼠标悬停与键盘聚焦图标按钮时，均出现该按钮的功能说明文字。
2. 说明文案与控件可访问名称（`aria-label`）含义一致；控件保留非空可访问名称。
3. 提示出现/退出本身有轻微过渡，不打断用户操作节奏，不遮挡用户正在查看或操作的内容。
4. 提示文案为中文，与界面语言一致。
5. 提示样式在浅色与深色主题下均可读。
6. 推荐基线：悬停后约 300–500ms 延迟出现，避免鼠标掠过时频繁闪现；实现方式（自定义提示组件或其他）由设计阶段决定，不作为需求约束。

### M5 既有功能与数据行为保持

- 交互与反馈方式可以调整，以下功能语义与结果不得变化：创建任务、内联编辑（标题/描述/优先级/截止日期）、拖拽改列、删除与约 5 秒内撤销、按标题搜索、深色模式切换、列隐藏与恢复、JSON 导出、存储异常提示、数据损坏恢复。
- 既有保存数据在本次改动后仍可正常读取，不要求用户清除数据或迁移格式。
- 持久化读取入口与行为保持：页面刷新或重新打开后，任务与偏好（主题、列可见性等既有已保存项）按原语义恢复。

## 5. 非功能要求

- 数据兼容：本次改动不得使既有用户数据不可读。
- 本次需求不包含对技术栈、存储方式、构建方式的变更要求。

## 7. 验收场景

适用角色统一说明：本地单用户工具，无角色分级，以下各条适用角色均为「看板使用者（不区分角色）」。所有验收均为用户可发现的浏览器入口。

### AC-01 视觉层级简约统一

- 强制程度：强制
- 入口类型：UI/浏览器
- 前置条件：应用以浅色主题打开，看板包含至少两列、多张卡片
- 动作：观察首屏整体布局与头部、搜索、列头、卡片、徽章、按钮等元素
- 预期结果：同类元素间距/圆角/阴影规格一致；标题、次要、弱化三级文字层级可辨；无多余装饰性噪声（重复描边、过重阴影）；留白适度不拥挤
- 证据类型：浏览器实际计算样式与布局读数（visual-style）

### AC-02 浅色主题配色舒适

- 强制程度：强制
- 入口类型：UI/浏览器
- 前置条件：浅色主题
- 动作：观察页面背景、正文、卡片、按钮与徽章配色
- 预期结果：正文与背景对比充足（普通文字不低于 4.5:1，正文主文本达到约 7:1 量级或更高，按推荐基线）；无高饱和刺眼色块；可点击元素颜色可辨识
- 证据类型：浏览器实际计算样式（颜色与对比读数，visual-style）

### AC-03 深色主题配色舒适

- 强制程度：强制
- 入口类型：UI/浏览器
- 前置条件：深色主题（点击深色切换）
- 动作：观察与浅色相同的元素集合
- 预期结果：主题全局生效；背景非大面积纯黑；正文对比充足且不刺眼；优先级等语义色在深色下可辨识；无主题切换错色闪烁
- 证据类型：浏览器实际计算样式（visual-style）

### AC-04 控件悬停与按下反馈

- 强制程度：强制
- 入口类型：UI/浏览器
- 前置条件：任一主题，看板含卡片与图标按钮
- 动作：依次悬停卡片、悬停并按下按钮
- 预期结果：悬停与按下均有平滑的视觉反馈变化（无瞬时跳变）；反馈样式在两主题下均可见
- 证据类型：真实交互前后的状态变化与样式读数（interaction / visual-style）

### AC-05 状态切换过渡平滑

- 强制程度：强制
- 入口类型：UI/浏览器
- 前置条件：看板含多列与任务
- 动作：依次执行——打开/取消任务编辑器、隐藏再恢复一列、触发删除撤销提示、（如可触发）观察错误提示出现
- 预期结果：上述元素的出现/退出均有短暂过渡而非瞬时显隐；过渡节奏一致；过渡不阻塞下一步操作
- 证据类型：真实交互后的可观察变化（interaction）

### AC-06 拖拽反馈连贯

- 强制程度：强制
- 入口类型：UI/浏览器
- 前置条件：看板至少两列各含任务
- 动作：将一张卡片拖拽到另一列并松手
- 预期结果：拖拽中目标列/落点有连续反馈；松手后卡片出现在目标列且状态相应变化，无突兀跳变；数据与刷新后一致
- 证据类型：真实交互后的状态变化（interaction）

### AC-07 图标按钮功能说明（悬停与键盘聚焦）

- 强制程度：强制
- 入口类型：UI/浏览器
- 前置条件：任一主题，页面含图标按钮（导出、恢复列、深色切换、列头隐藏等）
- 动作：分别以鼠标悬停、Tab 聚焦各图标按钮
- 预期结果：两种方式都能看到该按钮的功能说明文字；文案与可访问名称含义一致；提示不遮挡正在进行的操作；移开/失焦后提示消失
- 证据类型：真实交互后的提示出现/消失（interaction）；可访问名称核对

### AC-08 减少动态效果降级

- 强制程度：推荐
- 入口类型：UI/浏览器
- 前置条件：系统/浏览器开启「减少动态效果」偏好
- 动作：执行与 AC-04/AC-05 相同的交互
- 预期结果：过渡动效降级（缩短或移除），功能与状态变化仍完整可达
- 证据类型：样式降级读数（visual-style）

### AC-09 提示双主题可读

- 强制程度：推荐
- 入口类型：UI/浏览器
- 前置条件：浅色与深色主题各一次
- 动作：触发图标按钮提示
- 预期结果：提示在两主题下均清晰可读（文字与提示底色对比充足）
- 证据类型：样式读数（visual-style）

### AC-10 既有功能与持久化不回归

- 强制程度：强制
- 入口类型：UI/浏览器
- 前置条件：看板可正常打开（存在既有保存数据时直接使用，不要求清空）
- 动作：依次创建任务、内联编辑、拖拽改列、删除并在撤销窗口内恢复、按标题搜索、隐藏并恢复列、切换主题、导出，然后刷新页面
- 预期结果：所有操作结果与既有语义一致；刷新后任务与已保存偏好按原语义恢复
- 证据类型：真实交互后状态变化 + 刷新后读回（interaction / session-persistence）
